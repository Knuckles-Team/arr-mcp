# CONN-ARR-MCP-SUITE — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it. The generator sets each row's state in `status.json`.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-ARR-MCP-SUITE-R001` | **Every upstream operation is one tool.** The connector must serve one typed tool for each upstream API operation of Radarr, Sonarr, Lidarr, Prowlarr, Chaptarr, Bazarr and Seerr. The census fixture `tests/fixtures/upstream_operations.json` lists 1,373 operations from the upstream API descriptions; it excludes only the web-sign-in routes. `scripts/generate_api_client.py` writes `arr_mcp/api/api_client_bazarr.py` (84 operations, from the live Bazarr `/api/swagger.json`; row R009 adds the 4 operations Bazarr hides from it) and `arr_mcp/api/api_client_seerr.py` (217 operations). `arr_mcp/api/api_client_sonarr.py` adds `get_rename_bulk`. Caller chain: `arr_mcp:connector` (`arr_mcp/__init__.py`) `verbose_targets` -> `scion_sdk.mcp.tool_surface.register_tool_surface` -> one tool `<app>_<method>` per public client method. Shape: one `Api` method per operation in each `arr_mcp/api/api_client_<app>.py`, with `Annotated[<type>, Field(description=...)]` keyword parameters; the methods reuse `Api._request` and `arr_mcp/api/_security.py`. | Each fixture operation has a client method, each client route is an upstream operation, and each method is a served tool. Test: `tests/test_suite_surface.py::test_every_upstream_operation_has_a_client_method`, `tests/test_suite_surface.py::test_every_client_method_is_served_as_a_tool`. |
| `CONN-ARR-MCP-SUITE-R002` | **Typed tools only.** The connector must serve no `action`-routed tool, no `params_json` parameter and no raw request tool. Each client keeps its HTTP helper private as `Api._request`, so the SDK serves no `<app>_request` tool. Every DELETE tool carries `destructiveHint` and asks for confirmation. Files: `arr_mcp/api/api_client_*.py`. Caller chain: `arr_mcp:connector` -> `register_tool_surface` -> `register_method_tools`, which skips methods whose name starts with `_`. Shape: `def _request(self, method, endpoint, params=None, data=None, form=None)` in each client; `arr_mcp/mcp/__init__.py` exports only `register_kg_tools`. | No served tool has `params_json`, an `_action` name, or `method` plus `endpoint` parameters; every delete tool is destructive. Test: `tests/test_suite_surface.py::test_no_action_routed_or_raw_request_tool`, `tests/test_suite_surface.py::test_deletes_ask_for_confirmation`. |
| `CONN-ARR-MCP-SUITE-R003` | **The response boundary refuses web pages.** `arr_mcp/api/_security.decode_response` must raise `NOT_AN_API_RESPONSE` when an app answers with `text/html`. Before this row, a wrong Bazarr route returned the web page as `status: success`. `send_request` sends `form` as a form body and `data` as a JSON body. Bazarr query fields travel as query parameters, and Seerr body fields travel as JSON keys with their upstream names. Caller chain: a served tool -> `Api.<method>` -> `Api._request` -> `send_request` and `decode_response` in `arr_mcp/api/_security.py`. Shape: `_refuse_html(response)` raises `RuntimeError` with the `NOT_AN_API_RESPONSE` code; `send_request(client, method, url, params, data, *, form=None)`. | An HTML answer raises `NOT_AN_API_RESPONSE`; the Bazarr and Seerr requests carry the upstream paths and field names. Test: `tests/test_suite_surface.py::test_an_html_page_is_refused_not_reported_as_success`, `tests/test_suite_surface.py::test_bazarr_routes_and_query_parameters_match_the_live_api`, `tests/test_suite_surface.py::test_seerr_body_fields_travel_as_json`. |
| `CONN-ARR-MCP-SUITE-R004` | **Skills carry the task workflows as tool-use contracts.** The package must ship one skill per app plus `arr-download-queue` and `arr-mcp-operations` in `arr_mcp/skills/<skill>/SKILL.md`. Each workflow is an `arr:ToolUseContract` in `arr_mcp/ontology/arr-contracts.ttl`, with ordered `arr:ContractStep` nodes, one `arr:callsTool` each, and `arr:ParameterBinding` nodes for the parameters. 28 contracts cover add-and-search, missing-item search, the download queue, failing indexers, subtitles, requests and suite health; row R011 adds the 6 provisioning workflows. The SDK serves the skills as `skill://` resources and the ontology as `ontology://arr-mcp/<file>.ttl`. Caller chain: `arr_mcp:connector` -> the SDK content tier, which serves `arr_mcp/skills/*/SKILL.md` and `arr_mcp/ontology/*.ttl` (`CONN-ARR-MCP-CONNECTOR-CONTENT-R001`). Shape: `arr:ToolUseContract` -> `arr:hasStep` -> `arr:ContractStep` (`arr:stepIndex` integer, `arr:callsTool`, `arr:needsApproval` boolean, `arr:precedesStep`) -> `arr:bindsParameter` -> `arr:ParameterBinding` (`arr:parameterName`, `arr:parameterSource` strings); see [data-model.md](data-model.md). | Every contract tool is served; every app has contracts; steps are numbered 1..n with one tool each; skills name only served tools. Test: `tests/test_suite_surface.py::test_contract_tools_are_served`, `tests/test_suite_surface.py::test_every_app_has_a_skill_and_contracts`, `tests/test_suite_surface.py::test_contract_steps_are_ordered_and_bound`, `tests/test_suite_surface.py::test_skill_files_name_only_served_tools`. |
| `CONN-ARR-MCP-SUITE-R005` | **Prompts are agent definitions.** The package must ship one operator prompt (`arr_operator`) and one prompt per business role (`media_librarian`, `request_manager`, `indexer_maintainer`, `subtitle_curator`, `download_monitor`) in `arr_mcp/prompts/<name>.json`. Each prompt has `role: system`, a `systemPromptFor` role class IRI, and a `core_directive` that states the goal, skills, contracts, data locations, guardrails and outputs. Each prompt is an `arr:ConnectorPrompt` linked with `arr:usesSkill`, `arr:runsContract`, `arr:usesTool` and `arr:systemPromptForRole`. Caller chain: the SDK prompt provider (`scion_sdk.mcp._content_prompts`) serves each `arr_mcp/prompts/*.json` as one MCP prompt whose text is `instructions.core_directive`. Shape: JSON keys `role`, `systemPromptFor`, `identity`, `instructions.core_directive`, `data_locations`, `guardrails`, `outputs`, `skills`, `contracts`, `tools`; ontology node `arr:prompt-<name>`. | Each prompt is served, names only served tools, has every section, and its ontology links equal its tool list. Test: `tests/test_suite_surface.py::test_operator_and_role_prompts_exist`, `tests/test_suite_surface.py::test_prompt_is_a_complete_agent_definition`. |
| `CONN-ARR-MCP-SUITE-R006` | **Data location, routing and federation.** `arr_mcp/ontology/arr.ttl` must record each app as an `arr:SuiteApp` with one `arr:AppInstance`. Each instance records its base-URL and API-key setting names, never their values, and the library it holds. A library records its root folder (`/movies`, `/tv`, `/music`). `arr:RoutingRule` nodes map a core media class to the instance that holds it. `arr:FederationLink` nodes record the Prowlarr indexer sync, the Seerr request forwarding and the Bazarr subtitle links. Caller chain: the SDK content tier serves `ontology://arr-mcp/arr.ttl`; arbora onboarding reads it. Shape: `arr:app-<app>`, `arr:instance-<app>`, `arr:library-<app>`, `arr:rootfolder-<app>`, `arr:route-<Class>-<app>` and `arr:federation-<src>-<kind>-<dst>` individuals; see [data-model.md](data-model.md). | Every app has an instance, a library and its setting names; there are at least 5 routes and all 3 federation kinds. Test: `tests/test_suite_surface.py::test_every_app_has_an_instance_library_and_settings`, `tests/test_suite_surface.py::test_routing_and_federation_are_recorded`. |
| `CONN-ARR-MCP-SUITE-R007` | **Every class rolls up to medulla core.** Every class in `arr_mcp/ontology/*.ttl` must be in the `https://knuckles-team.github.io/ontology/connector/arr#` namespace and subclass a medulla core class. Through core, every class reaches `bfo:Entity` (`BFO_0000001`). The files hold no `owl:imports`. The connector redeclares no core class: the earlier `:Movie`, `:Series`, `:Episode`, `:Indexer` and `:QualityProfile` declarations are gone. The test reads core from the `medulla` wheel of the `test` extra. Caller chain: the SDK content tier serves both Turtle files; the engine merges them with core. Shape: each class is `arr:<Name> rdfs:subClassOf :<CoreClass>`; the core parents are listed in [data-model.md](data-model.md). | No import; every arr class has a core ancestor and reaches `BFO_0000001`; held media classes are core classes. Test: `tests/test_suite_surface.py::test_no_ontology_imports`, `tests/test_suite_surface.py::test_every_class_reaches_medulla_core_and_bfo_entity`, `tests/test_suite_surface.py::test_media_classes_the_library_holds_are_core`. |
| `CONN-ARR-MCP-SUITE-R008` | **Ingest uses core classes and served tools.** `arr_mcp/kg_ingest.py` must emit the core classes `Film`, `Series`, `MediaIndexer` and `QualityProfile`. The presets in `arr_mcp/ontology/mappings/source.yaml` must name served typed tools (`radarr_get_movie`, `sonarr_get_series`, `prowlarr_get_indexer`) with their current schema pins. Caller chain: the `arr_ingest_library` tool (`arr_mcp/mcp/mcp_kg.py`) -> `ingest_movies`, `ingest_series` and `ingest_indexers` (`arr_mcp/kg_ingest.py`) -> `SourceStream.entities`. Shape: `node_type` values `Film`, `Series`, `MediaIndexer`, `QualityProfile`; presets `tool` plus `tool_schema_sha256`, with no `action` key. | Every preset tool is served with a matching pin; every emitted node type is a core class. Test: `tests/test_suite_surface.py::test_ingest_presets_name_served_tools_with_current_pins`, `tests/test_suite_surface.py::test_ingest_node_types_are_medulla_core_classes`. |
| `CONN-ARR-MCP-SUITE-R009` | **Bazarr's hidden operations are tools.** Bazarr 1.6.2 serves `system/settings` (GET, POST), `system/notifications` (PATCH) and `system` (POST restart or shutdown) but hides them from its swagger with `Namespace.hide`, so the generated client had no way to connect Bazarr to Sonarr and Radarr, enable a provider or set a language profile. `arr_mcp/api/api_client_bazarr.py` must add `get_system_settings`, `post_system_settings`, `patch_system_notifications` and `post_system`; the census fixture lists them under `bazarr` with a `hidden_from_swagger` note. `post_system_settings` takes one typed `settings` mapping and posts it as the settings page's form (`settings-<section>-<key>`, `languages-enabled`, `languages-profiles`), a list repeating the field and a boolean as `true`/`false`. `system/account` (web sign-in) stays excluded. Caller chain: `arr_mcp:connector` -> `register_tool_surface` -> `bazarr_post_system_settings` -> `Api.post_system_settings` -> `Api._request(form=...)` -> `send_request`. Shape: `def post_system_settings(self, *, settings: dict[str, Any]) -> Any`. | The settings save posts a form with repeated list fields and lower-case booleans; the four tools are served. Test: `tests/test_suite_surface.py::test_bazarr_settings_save_posts_the_settings_page_form`, `tests/test_suite_surface.py::test_bazarr_hidden_operations_are_served`. |
| `CONN-ARR-MCP-SUITE-R010` | **A failed call says why, and long calls get time.** Before this row every client raised `API error: HTTP 400` and dropped the body, so an agent could not see `Host: Unable to connect to qBittorrent`, `folderType` missing or a Cloudflare block; and the 30-second read timeout reported indexer tests, FlareSolverr challenges and subtitle provider searches (up to 212 s live) as `Upstream timed out`. `arr_mcp/api/_security.raise_for_api_error` must read a bounded error body (16 KiB) and raise `API error: HTTP <status>: <reason>`, flattening Servarr validation lists (`propertyName: errorMessage`), ASP.NET `errors` maps and `message`/`detail` fields to at most 1,500 characters, and naming an HTML answer as a web page instead of dumping it. Every generated client and `scripts/generate_api_client.py` call it. `REQUEST_TIMEOUT` read and `_MAX_RESPONSE_SECONDS` are 300 s. Caller chain: a served tool -> `Api.<method>` -> `Api._request` -> `raise_for_api_error(response)`. Shape: `def raise_for_api_error(response: httpx.Response) -> None`. | Each body shape yields its reason in the message; a proxy page is named; every client uses the shared boundary; timeouts are at least 300 s. Test: `tests/test_suite_surface.py::test_a_failed_call_raises_with_the_upstream_reason`, `tests/test_suite_surface.py::test_a_proxy_error_page_is_named_not_dumped`, `tests/test_suite_surface.py::test_every_client_raises_through_the_shared_boundary`, `tests/test_suite_surface.py::test_long_upstream_operations_have_minutes_not_seconds`. |
| `CONN-ARR-MCP-SUITE-R011` | **Provisioning workflows proven live are contracts.** The six workflows run against the live suite on 2026-11-06 must be `arr:ToolUseContract` nodes in `arr_mcp/ontology/arr-contracts.ttl`, sections of their skill and runs of their prompts: `bazarr-connect-sonarr-radarr` and `bazarr-enable-free-providers` (`arr-subtitle-management`, `subtitle_curator`), `arr-repair-download-client` (`arr-download-queue`, `download_monitor`), `chaptarr-provision-book-library` (`arr-book-library`, `media_librarian`), `prowlarr-replace-dead-indexer` (`arr-indexer-management`, `indexer_maintainer`) and `seerr-route-requests-by-quality` (`arr-media-requests`, `request_manager`); `arr_operator` runs all six. Steps that change connections, credentials, indexers or routing carry `arr:needsApproval true`, and the guardrail allows a credential change only in such a step with keys read from the credential store. Caller chain: the SDK content tier serves the skills, prompts and `ontology://arr-mcp/arr-contracts.ttl`. Shape: as R004 and R005. | The R004 and R005 tests hold for the new contracts and prompt links; each new contract exists with its approval steps. Test: `tests/test_suite_surface.py::test_provisioning_contracts_are_recorded_with_approval_steps`. |
| `CONN-ARR-MCP-SUITE-R012` | **Settings reads never return secret values.** `bazarr_get_system_settings` (R009) returned Bazarr's own API key, the Sonarr and Radarr API keys and the Plex encryption key in plain text to the caller and through arbora. `arr_mcp/api/api_client_bazarr._redact` must replace every secret-named field (`apikey`, `api_key`, `password`, `passkey`, `token`, `cookies`, `encryption_key`, `secret`, provider keys) with `"<set>"` when set and keep it empty when not, so an agent sees whether a credential is configured but never its value. Caller chain: `bazarr_get_system_settings` -> `Api.get_system_settings` -> `Api._request` -> `_redact`. Shape: `def _redact(value: Any) -> Any`. | Set secrets read `<set>`, empty ones stay empty, other values are unchanged and no secret value appears in the answer. Test: `tests/test_suite_surface.py::test_bazarr_settings_read_masks_secrets`. |
| `CONN-ARR-MCP-SUITE-R013` | **The whole surface is declared.** Every served tool is called by a tool-use contract step, linked to a prompt and a skill, and the operator and five business-role prompts are complete agent definitions with data locations and roles.
