| `CONN-ARR-MCP-SDK-CENTRALIZATION-R001` | **Capabilities come from the SDK (rollup).** The connector must use the SDK for HTTP, retry, TLS and optional dependencies. Children `.1` to `.4` deliver it. | See each child. |
| `CONN-ARR-MCP-SDK-CENTRALIZATION-R001.1` | **Governed client.** Every arr API client must send HTTP through the SDK governed client and must not import `requests` or `urllib3` (`SCION-CENTRALIZED-CAPABILITIES-R001`, `SCION-CENTRALIZED-CAPABILITIES-R003`). The service key must travel as SDK API-key auth in the `X-Api-Key` header. The generator must emit the same client. Shape: `build_client` in `arr_mcp/api/_security.py:78` uses `create_http_client`, `HttpClientOptions` and `ApiKeyAuth` from `scion_sdk`; each `api_client_<service>.py` holds that client and the generator emits the same file. | Each client holds an SDK client, sends the key header and imports no `requests`. |
| `CONN-ARR-MCP-SDK-CENTRALIZATION-R001.2` | **TLS profile only.** Each client must take transport trust from `resolve_tls_profile` for its service prefix (`SCION-CENTRALIZED-CAPABILITIES-R008`).
